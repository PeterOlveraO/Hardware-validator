# Hardware Validator v0.1.0 specification

Status: implementation contract for v0.1.0.

## Goal and scope

Hardware Validator v0.1.0 prints a concise inventory of the local computer. It
supports Linux and Python 3.11 or newer.

It collects:

- Computer, baseboard, and BIOS information.
- CPU identity, counts, frequencies, and a simplified cache summary.
- Installed RAM, current RAM usage, and detectable modules.
- Top-level storage devices visible to Linux.
- Integrated and dedicated GPU information.
- Local Ethernet, Wi-Fi, loopback, virtual, and unknown network interfaces.

It does not collect or perform:

- Stress tests, benchmarks, diagnostics, or hardware-health results.
- Swap or CPU instruction flags.
- Detailed CPU cache topology.
- Partitions, filesystems, mounts, disk usage, sectors, or read-only state.
- GPU connectors, DRM nodes, PCI addresses/classes, or primary state.
- Bluetooth, batteries, or peripherals.
- UI, TUI, JSON, telemetry, remote access, or interactive input.
- System commands, external applications, or remote services.

The approved dependency is `psutil==7.2.1`.

## General contract

- Public models are typed dataclasses with English identifiers.
- Unknown optional values are `None`; the report prints `Unknown`.
- Zero is a real value, never a substitute for unknown.
- Capacities use bytes, CPU frequencies use hertz, and RAM-module speeds use
  MT/s. Numeric values are non-negative integers.
- Collections are immutable tuples with deterministic ordering.
- Values must come from readable local sources and must never be guessed.
- Missing, protected, malformed, or unsupported optional data is normal.
- Detector failures are isolated so the remaining sections still print.
- The public contract contains no test, health, or detection-status fields.

### Internal detection result

Detectors return an internal `DetectionResult[T]` containing a public component
value, a `DetectionStatus`, and internal issue messages. Neither the wrapper nor
its status/issues are fields of `HardwareSnapshot` or printed as health results.

- `complete`: every selected source succeeded; an absent optional source is
  normal.
- `partial`: useful data exists, but a selected source was protected,
  malformed, unsupported, or failed.
- `unavailable`: the detector obtained no useful component data.

The collector retains these results through report rendering. An empty primary
inventory is printed as no devices detected only when its status is `complete`;
otherwise it is printed as `Unknown`. These states describe detection
completeness only, never hardware health or test outcomes.

## System

| Object | Field | Type |
| --- | --- | --- |
| `SystemInfo` | `manufacturer` | `str | None` |
|  | `model` | `str | None` |
|  | `architecture` | `str | None` |
|  | `baseboard` | `BaseboardInfo` |
|  | `bios` | `BiosInfo` |
| `BaseboardInfo` | `manufacturer` | `str | None` |
|  | `model` | `str | None` |
|  | `version` | `str | None` |
| `BiosInfo` | `manufacturer` | `str | None` |
|  | `version` | `str | None` |
|  | `release_date` | `str | None` |

Architecture comes from `os.uname()`. DMI maps `sys_vendor` and `product_name`
to the computer, `board_vendor`/`board_name`/`board_version` to the baseboard,
and `bios_vendor`/`bios_version`/`bios_date` to BIOS. Device Tree `model` is a
fallback only for computer model. Text is stripped; empty values and the
case-insensitive placeholders `Unknown`, `Not Specified`, `Default string`, and
`To Be Filled By O.E.M.` become `None`. BIOS date remains the reported string.

The Linux distribution, kernel version, system serial, and UUID are not
collected.

## CPU

### CpuInfo

| Field | Type |
| --- | --- |
| `model_names` | `tuple[str, ...]` |
| `vendor_ids` | `tuple[str, ...]` |
| `physical_package_count` | `int | None` |
| `physical_core_count` | `int | None` |
| `logical_processor_count` | `int | None` |
| `current_frequency_hz` | `int | None` |
| `maximum_frequency_hz` | `int | None` |
| `caches` | `tuple[CpuCacheInfo, ...]` |

### CpuCacheInfo

| Field | Type |
| --- | --- |
| `level` | `int` |
| `kind` | `Literal["data", "instruction", "unified"]` |
| `size_bytes` | `int | None` |

Names and vendors come from `/proc/cpuinfo`, retain first-seen distinct order,
and are empty when unavailable. Logical and physical counts use
`psutil.cpu_count(logical=True)` and `psutil.cpu_count(logical=False)`.
Package count is the number of distinct non-negative `physical_package_id`
values for all present CPUs; an incomplete topology yields `None` rather than
an undercount.

Frequency uses `psutil.cpu_freq(percpu=True)`: positive MHz values are converted
to hertz, current frequency is their rounded arithmetic mean, and maximum
frequency is their maximum. Missing, zero, or non-positive values are unknown.

Cache summaries use CPU sysfs `cache/index*` entries. Sizes with `K`, `M`, or
`G` suffixes use powers of 1024. Entries are reduced to unique `(level, kind,
size_bytes)` combinations and ordered by level, then data/instruction/unified,
then size with unknown last. Malformed entries are skipped and make detection
`partial`. No flags, minimum frequency, per-core entries, internal cache IDs,
line sizes, or shared-CPU lists are collected.

## Memory

### MemoryInfo

| Field | Type |
| --- | --- |
| `total_bytes` | `int | None` |
| `available_bytes` | `int | None` |
| `used_bytes` | `int | None` |
| `free_bytes` | `int | None` |
| `modules` | `tuple[MemoryModuleInfo, ...]` |

### MemoryModuleInfo

| Field | Type |
| --- | --- |
| `locator` | `str | None` |
| `manufacturer` | `str | None` |
| `part_number` | `str | None` |
| `serial_number` | `str | None` |
| `size_bytes` | `int | None` |
| `memory_type` | `str | None` |
| `speed_mt_s` | `int | None` |

RAM values use `psutil.virtual_memory()`. Total must be positive and available
and free must be between zero and total. `used_bytes` is calculated as total
minus available. Values are bytes and one observation, not a performance result.

Modules use readable SMBIOS type 17 data first; EDAC `dimm*` entries are a
fallback only when SMBIOS is unavailable or unusable. SMBIOS Configured Memory
Speed takes precedence over nominal Speed, including their extended fields, and
is stored in MT/s. EDAC provides no module speed, manufacturer, part number, or
serial unless those exact values are exposed, so they remain `None`.

An internal SMBIOS handle or canonical EDAC path orders modules; it is not a
public field. If firmware data is protected, `modules` is empty and memory
detection is `partial` while total/current RAM may remain available. Ranks,
voltage, timings, and error counters are not collected.

## Storage

### StorageInfo

| Field | Type |
| --- | --- |
| `disks` | `tuple[DiskInfo, ...]` |

### DiskInfo

| Field | Type |
| --- | --- |
| `name` | `str` |
| `device_path` | `str | None` |
| `vendor` | `str | None` |
| `model` | `str | None` |
| `serial_number` | `str | None` |
| `size_bytes` | `int | None` |
| `rotational` | `bool | None` |
| `transport` | `str | None` |
| `removable` | `bool | None` |

Inventory uses `/sys/class/block` and represents top-level storage devices
visible to Linux, including kernel-composed or virtual devices; it does not
claim they are physical. Partitions, loop devices, zram, RAM disks, and optical
drives are excluded through kernel attributes rather than name-only guesses.

`size_bytes` is the valid non-negative block `size` value multiplied by 512,
not by another sector size. `rotational` accepts only queue `0` as `False` and
`1` as `True`; it is never translated into HDD or SSD. Transport is the first
explicit `nvme`, `virtio`, `mmc`, `ata`, or `usb` subsystem in canonical device
ancestry. Generic `scsi` remains `None`. Disks are ordered by kernel name;
missing optional attributes remain `None`.

## GPU

### GpuInventory

| Field | Type |
| --- | --- |
| `devices` | `tuple[GpuInfo, ...]` |

### GpuInfo

| Field | Type |
| --- | --- |
| `commercial_name` | `str | None` |
| `vendor_id` | `str | None` |
| `device_id` | `str | None` |
| `adapter_type` | `Literal["integrated", "dedicated"] | None` |
| `memory_total_bytes` | `int | None` |
| `driver` | `str | None` |

Discovery uses local DRM and PCI sysfs interfaces. Each candidate receives an
internal identity equal to its canonical device path under `/sys/devices`.
DRM and PCI records resolving to that path are merged once, and final devices
are ordered lexically by that identity. The identity is neither a `GpuInfo`
field nor report output.

PCI display-class devices and DRM devices with a canonical backing device are
eligible. Numeric IDs use lowercase `0x` plus four hexadecimal digits. Driver
is the bound driver symlink basename. Commercial name uses documented amdgpu
`product_name`, then a valid local PCI VPD Identifier String; malformed
higher-precedence data permits fallback and makes detection `partial`. IDs are
never translated through a database, remote service, or external application.

`adapter_type` is set only by an explicit documented local classification; no
vendor, PCI address, driver, or memory heuristic is allowed. Documented amdgpu
CEM/OAM `board_info` may establish `dedicated`; otherwise the field is `None`.
`memory_total_bytes` uses only a valid non-negative amdgpu
`mem_info_vram_total`. Zero is valid. Shared RAM, GTT limits, and PCI BAR sizes
are never reported as graphics memory. Missing optional sources remain `None`.

### NetworkGatewayInfo

| Field | Type |
| --- | --- |
| `address` | `str` |
| `ip_version` | `Literal[4, 6]` |
| `interface_name` | `str | None` |
| `metric` | `int | None` |

Discovery merges one local observation from `psutil.net_if_addrs()`,
`psutil.net_if_stats()`, and `/sys/class/net`. IPv4 masks come from the address
observation. Default routes come only from `/proc/net/route` and reliably parsed
entries in `/proc/net/ipv6_route`. Configured DNS comes from `/etc/resolv.conf`;
optional upstream DNS remains distinct and comes only from readable
`/run/systemd/resolve/resolv.conf`. Interfaces are ordered by canonical sysfs
identity, addresses and routes are deterministic, speed is retained in Mbps, and
zero speed means unknown.

Classification never uses interface-name prefixes. Linux ARPHRD type 772
establishes loopback; `wireless` or `phy80211` sysfs evidence establishes Wi-Fi;
a canonical `/sys/devices/virtual/net` identity establishes virtual; and a
wireless marker or ARPHRD type 1 establishes Wi-Fi or Ethernet only with a
resolved non-virtual identity and explicit backing `device`. Insufficient or
unreadable classification evidence produces `unknown`.

Only unicast default routes without an IPv6 source selector are retained. The
public gateway model cannot represent policy-routing selectors, so
source-specific IPv6 routes are not presented as system-wide gateways. Rejected
routes are ignored. A gateway is associated only with an interface present in
the same inventory. A local stub such as `127.0.0.53` remains configured DNS and
is never described as the upstream resolver without the separate
systemd-resolved source. Malformed route or DNS candidates never turn an
otherwise empty result into a confirmed absence; the affected collection stays
unknown.

Detection performs no active route lookup, DNS request, connectivity probe,
Wi-Fi scan, packet operation, socket connection, external command, or remote
query. State, addresses, routes, DNS, speed, MTU, and duplex are transient local
observations, not health results.

## Permissions and failures

The program must work without administrator privileges. Running it with `sudo`
is optional and may reveal additional RAM-module, firmware, disk-serial, or GPU
details. For an attempted optional source, `PermissionError` changes its scalar
to `None` or its collection to empty and makes the internal result `partial`.
An absent optional source is normal and does not prevent `complete`.

The program exits with an error for an unsupported Python or operating system
version, a missing/incompatible required dependency, an internal contract or
programming violation, invalid command-line arguments, or inability to write the
final report. An operational detector failure represented by `OSError` or
`NotImplementedError` produces an `unavailable` internal result with an unknown
or empty public component and does not stop other detectors. Every other
unexpected exception is treated as a fatal programming error rather than hidden
as unavailable hardware. Model and result invariant failures are also outside
the detector-recovery boundary.

`InventoryDetectors` validates that all six components provide a callable
`detect()` method. `InventoryResults` validates every result wrapper and public
component type before report rendering, so the presentation layer always
receives objects that satisfy the aggregate contract.

## Dependency

| Dependency | Version | Purpose |
| --- | --- | --- |
| `psutil` | `==7.2.1` | CPU, RAM, mounts, and local network-interface values. |

Detection must not execute commands, open network connections, or depend on a
background service. The reviewed Linux implementations of the selected psutil
APIs read `/proc`, `/sys`, or native operating-system APIs and require no root
access. The exact version is declared in `pyproject.toml`; missing or mismatched
runtime versions are fatal startup errors.

## Package architecture

```text
pyproject.toml
src/hardware_validator/
    __init__.py
    __main__.py
    models.py
    collector.py
    report.py
    detectors/{system,cpu,memory,storage,gpu,network}.py
tests/
```

Each detector returns an internal `DetectionResult` wrapping one public
component object. `collector.py` isolates detectors and retains internal status
through rendering, `report.py` formats plain text without exposing that status,
and tests use mocks and fixture files instead of the developer's hardware.

### Terminal output levels

The default command renders a concise `Computer`, `Processor`, `Memory`,
`Storage`, `Graphics`, and `Network` summary. It omits firmware, topology
details, swap, partitions, mounts, hardware addresses, and connectors. The
network summary is the exception for local addressing: physical Ethernet and
Wi-Fi show MAC, assigned IPv4 values, subnet masks, associated IPv4 default
gateway, and system-wide configured DNS. It omits IPv6, MTU, duplex, loopback,
virtual, and unknown interfaces. Empty or unverifiable RAM-module details are
shown as `Unknown`, not as proof that no modules exist. Virtual and removable
storage are omitted only when their existing model classification establishes
that fact.

`--verbose` renders the complete technical inventory from the same collected
`InventoryResults`; presentation never performs detection. Both modes preserve
deterministic ordering, unit conversion, `Unknown` values, and control-character
escaping. The technical report is written to stdout and can be saved with shell
redirection, while fatal errors remain on stderr.

Reproducible project commands:

```text
python -m pip install -e .
python -m hardware_validator
python -m hardware_validator --verbose
python -m unittest discover -s tests -v
python -m compileall -q src tests
```

## Completion criteria

1. Implement exactly the public fields and absence rules above.
2. Print only the included information, using `Unknown` when needed.
3. Handle missing, malformed, and permission-denied optional sources.
4. Test every detector, internal completeness states, isolation behavior, and
   report formatting without exposing statuses as health results.
5. Pass the unit suite, syntax checks, and a non-root Linux smoke run.
6. Introduce no hardware tests, benchmarks, subprocesses, external applications,
   or network access in the product.
